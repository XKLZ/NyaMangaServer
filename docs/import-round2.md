## 故障与修复

系列增量块允许省略空召回映射；Go反序列化得到nil后再次通过工作器协议发送为JSON null，Python原来对其调用`.items()`，引发未被捕获的AttributeError。两次独立查找和第二轮导入的系列子任务在相同旧证据恢复位置失败，发生在首次行比较之前，不能据此判断系列召回质量。只读重放已能复现，未运行模型推理；具体任务身份保存在私有交接材料。

修复在Go协议出口将缺失集合规范为`[]`／`{}`，Python同时兼容缺失、null和空集合。非法检查点返回`invalid_series_checkpoint`，Go映射为`series_checkpoint_invalid`；未预期异常返回脱敏`recommendation_worker_failed`，工作器仍能处理后续合法请求。现有有效证据不删除，不要求重新下载模型或重新计算全部特征。评分、门槛、聚类、模型、名称和排序规则不变。

系列工作器持久记录有限枚举阶段与错误类别，写入受任务执行代次保护，日志和API不返回原始异常、文件名、路径、凭据或题名：

| phase | 含义 |
|---|---|
| prepare_features | 准备特征 |
| restore_checkpoint | 建立当前池并恢复证据 |
| compare | 比较与检查点保存 |
| generate_proposals | 生成方案 |
| publish | 发布方案及完成 |

reason限定为`runtime_unavailable`、`invalid_checkpoint`、`resource_budget`。`GET /series-discovery-jobs/{id}`增量统计可包含`diagnostics`；导入批次失败摘要附同样的脱敏信息。旧任务没有诊断时不补造阶段。

## 失败、重试与明确跳过

版本／系列子任务失败或终止时，当前批次进入failed，不能显示为正常空建议。当前尝试按`import_child_requests`持久预留顺序确定，不使用随机ID顺序或秒级时间判断。重试建立新任务，旧失败保留；过时且尚未创建的预留不阻挡新尝试及审核门禁。元数据分块任务继续全部参与关卡，不按单个最新请求替代。

- `POST /import-batches/{id}/control/retry`：冻结批次revision，新建推荐尝试，复用可验证证据。
- `POST /import-batches/{id}/control/skip_recommendation`：只适用于当前失败的版本／系列阶段，记录关联任务与时间，返回review，不修改组织、不跨关。
- 后续仍由用户显式完成归属审核并继续。空建议、明确跳过和推荐失败是三种不同情况。
- 旧完成批次及任务不自动重开／重跑，也不改写历史状态；查询仍显示其中曾失败的子任务。
