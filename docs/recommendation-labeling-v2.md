# 漫画关系标注v2：新300对候选

日期：2026-10-16。本阶段仅准备样本；用户标注完成后才启动实验Agent进行分析与算法改进。正式应用、数据库与管理台没有接入推荐功能。

## 为什么重新建样本

用户确认旧评审中的“相同作品／系列”按“同作品或同系列”理解，旧same标签混合了两种关系。因此旧版分数重叠、正例覆盖等数字不再作为版本／系列推荐质量依据；原80条仍保留，不自动映射或纠正。模型转换、耗时、内存和缓存验证仍有效。

## 候选与隔离

唯一输入仍是用户提供的TreeC.sqlite与Covers副本。使用现有固定模型离线补算特征，旧缓存校验后复用；不联网、不新增模型、不调参、不读取源漫画。特征补算覆盖整个副本是为了多路选样，不属于准确率评估或NAS验收。

新包300对、10批、每批30对；排除旧包已评审配对，同一本书可参与其他配对：

| 方向（不向标注者展示） | 配额 |
|---|---:|
| 既有版本组线索／多路同作品候选 | 50／50 |
| 既有系列不同逻辑条目／标题语义系列候选 | 50／50 |
| 容易混淆的候选／普通候选 | 80／20 |

方向不是人工真值。多路候选以固定顺序轮流取样；某路线没有满足条件的候选时从同一类其他路线补齐，并记录实际路线数量。覆盖同作者不同作品、不同序号、相近封面不同题名、语义相近及同画廊不同组织等情况。每个已知族初始限制4次出现，配额不足时按6／8／12的固定上限放宽并记录，最高12次。

按组织关系及版本化标题核心构成的已知族预分210对校准／90对测试。任何已知族不得跨集，测试侧不包含上一轮评审书籍所在的已知族。未知语义同族仍需人工复核，正式评估前重新冻结族划分；不能用当前自动族划分宣称完全无泄漏。

## 如何标注

打开新包的review.html，每对只判断一次：

| 选项 | 定义 |
|---|---|
| 同一作品，不同版本 | 同一内容的语言、彩色、修订等版本；内容基本相同的重复文件也归此类 |
| 同一系列，不同作品或卷篇 | 第1／2卷、上下篇等不同逻辑条目；仅同作者、角色或题材不够 |
| 两者都不是 | 没有上述关系 |
| 无法确定 | 信息不足，不强迫归类 |

“合集／部分内容重叠”为独立备注标记，不自动变成同版本或同系列。理由可选。页面显示完整标题、封面缩略图、页数、语言及已有标签，不展示原组织、采样方向、分数或划分。

每批30对；支持前后切换、未完成筛选和1–4快捷键。输入框内不触发快捷键。浏览器草稿自动记住但不是文件保存；完成一批后点击“导出完整300对JSON”，下载名为labels.user.v2.json。所有批次均包含在导出中，未完成项为null；下次导入这个文件继续。导入错误不会覆盖当前草稿，未导出修改在关闭时提示。

完整标注应放在新包目录，用户确认保存完成后才校验并派发实验Agent。原包与旧标注不覆盖。不要将私人封面、标题、源ID或JSON放入Git。

## 命令与格式

从仓库根目录运行：

```sh
PYTHONDONTWRITEBYTECODE=1 .runtime/cache/recommendations/venv/bin/python experiments/recommendations/study.py prepare-v2
```

默认输出`.runtime/tests/runs/recommendations/run-v2/`。首次冻结白名单书籍输入，再顺序执行三个离线特征子进程；每项特征原子落盘，取消后同命令可续算。已有完整候选包拒绝覆盖；再次执行应显式给出新的运行目录。旧run-v1三个关键文件的SHA256在生成前后复核，不更改原件。

标注采用`recommendation-labels-v2`：pack_id及完整annotations列表；每项有pair_id、label（same_work／same_series／unrelated／uncertain／null）、collection_or_partial_overlap布尔值和reason字符串。要求全部配对恰好出现一次；不接受v1的same标签、缺条目、重复／未知ID或其他候选包。UI通过白名单嵌入展示数据，私有完整候选清单另存。v2包暂拒绝旧score/evaluate命令，避免错误套用二分类评估。

准备完成仅检查候选唯一性／配额／族隔离、封面与权限、四类标注、完整导入导出和脚本安全；不重新执行模型冷跑、应用全套或部署测试。验证结果在实际生成后登记。
