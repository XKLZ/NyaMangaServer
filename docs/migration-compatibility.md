# TreeC 迁移兼容性与转换工具约定

## 导入批次与转换边界

现行代码状态和迁移版本见[README](../README.md)与[迁移说明](../migrations/README.md)。TreeC转换不得把旧任务、推荐或审核决定导入为待执行批次。历史有效资料直接保留其来源，不需伪造网络候选；批次候选、生命周期及派生推荐证据应排除常规中间包，目标自行建立新代次。001–011未改。见[完整导入](import-workflow.md)。

版本：v0.3；日期：2026-10-17；状态：设计契约，转换工具尚未实现。当前后端存储与重建边界见 [后端数据架构](backend-data-architecture.md)。

自007起的目标映射以第16节Work／Edition／File为准。前部保留矩阵中的“物理书籍/版本组/逻辑成员”是来源及历史称谓，不表示仍使用旧目标表；来源每条漫画现在映射Edition/File，版本组映射Work，Series引用Work。

## 1. 目标与边界

完整保留 TreeC 业务数据与人工劳动成果。语言差异不构成障碍，通过 SQLite、备份及结构化转换建立映射。工具属于 NyaMangaServer 仓库，独立命令行交付，首版只导入空目标库，不做双向同步或合并已有书库。

迁移工具不要求在新设备上运行 macOS 或 TreeC；来源偏好导出可以由独立 macOS 工具读取明确选择的副本。该导出不应为了迁移而改动 TreeC 项目。

v1.0 可从漫画文件建库，转换工具单独排期。新模型开发时必须审查是否会丢失已有业务语义。

## 2. 已核对的来源事实

来源是 TreeC 项目源码中的备份和偏好实现，本次没有读取生产数据库。

- .nyaehbackup 当前为包含 manifest.json、TreeC.sqlite 和可选 TagAssets 的目录包，不能假定为 ZIP。
- manifest 包含 formatVersion、schemaVersion、appVersion、createdAt、includesTagAssets 等字段。
- 当前备份 formatVersion 为 1；源码最近 schema 为 21。这是观测基线，不代表未来工具自动支持所有历史或未来版本。
- 备份使用 SQLite 一致性备份接口，普通复制活跃 TreeC.sqlite 可能遗漏 WAL。
- 源漫画、封面缓存、向量缓存、翻译缓存、凭据不在常规备份内。
- 保存搜索等偏好存于 UserDefaults，不在该备份中。

实现时需建立明确的支持版本清单与固定样本，未知版本 fail closed，不能通过忽略未知字段宣称完整兼容。

## 3. 输入材料

| 输入 | 必需性 | 说明 |
|---|---|---|
| 一致性源数据包或明确指定的数据目录 | 必需 | 目录输入先建立一致性数据库快照；白名单读取主库、封面及素材，不读取凭据 |
| 偏好导出 | 可选，但完整迁移时需提供 | 版本化 JSON；包含保存搜索及可兼容偏好，不含凭据 |
| 书库路径映射 | 必需 | 旧根目录到新书库 ID／根目录的显式对应 |
| 目标源漫画 | 阅读必需 | 用户单独复制或只读挂载；不存在的文件保留 missing 记录 |

路径映射使用边界完整的最长根路径匹配。拒绝越界相对路径和符号链接；多重匹配冲突进入报告，不能猜测。嵌套旧根目录必须由明确规则解析。

旧应用配置或生产目录不能作为隐式输入；所有输入必须由用户明确选定。

## 4. 数据保留矩阵

| 来源数据 | 目标处理 |
|---|---|
| 物理书籍、路径、文件信息、状态 | 建立稳定新 ID 与源 ID 映射，重映射根目录 |
| 代表图 SHA1 | 保留用于元数据查找，不作为去重唯一键 |
| gallery metadata、展示字段、标签 | 保存原始来源与当前有效值；不清楚来源的值保守保留 |
| 人工编辑 | 优先保留，禁止后续远端刷新无提示覆盖 |
| 系列、成员顺序 | 转为逻辑成员，保留次版本原顺序及其他差异用于审计 |
| 版本组、主版本、版本标签及历史建议值 | 保留语义；主版本异常或关系冲突必须报告 |
| 收藏、显式隐藏、结构隐藏 | 分别映射；结构隐藏不能变成用户隐藏 |
| 阅读页码、完成状态、次数、last_read_at | 按物理书籍保留，不能从 updated_at 推断 |
| 标签关注、作品角色人工确认／排除／逐书抑制 | 支持时转换，未支持时作为附件保留 |
| TagAssets 与专题配置 | 保留文件、配置、引用映射及内容摘要，不必首版展示 |
| 人工封面、人工翻译及其他不可重建素材 | 作为长期数据保留并登记来源；不能随封面／翻译缓存统一丢弃 |
| 保存搜索、阅读偏好 | 从偏好导出转换；不兼容表达式原样归档并报告 |
| 导入批次、待审核建议、任务历史 | 归档，不转换成新系统可执行任务 |
| 源文件删除操作日志 | 归档，绝不自动恢复源文件操作 |
| 自动封面、机器翻译缓存、向量及派生索引 | 自动封面可转换登记后复用；其他按兼容性重建或附件保留；不能将人工数据当缓存丢弃 |
| 凭据、设备窗口状态 | 不迁移，列入排除清单；凭据重新配置 |

暂不支持的数据必须有可读取的迁移附件与目录说明。附件不能仅为一句“未支持”；应包含原始值、来源表／字段或文件引用、源 ID 及内容校验摘要。保留副本不代表已支持对应产品功能。

## 5. 工具流程

1. 检查输入包结构、支持版本、数据库完整性、外键和素材引用；源只读。
2. dry-run：统计记录与关系，检查目标为空、路径映射、文件可用性和兼容差异，输出阻断项／警告。
3. 计算源快照摘要和转换版本，建立迁移运行 ID、旧新 ID 对照及逐类保留清单。
4. 在独立临时目标库转换；文件匹配以路径映射为主，必要时核验大小／内容指纹。重复 SHA1 不合并。
5. 校验书籍数、标签关系、系列顺序、主版本、阅读状态、素材与附件摘要。无法无损解释的关系进入阻断项，不静默修复。
6. 生成机器可读报告与人工摘要。警告列出原值与目标值；阻断项未解决不得激活。
7. 停止目标服务／进入维护状态后激活验证库，保存原始备份与激活前状态；异常回退。激活方式须在工程实现时覆盖同文件系统与跨文件系统安全行为。

源快照摘要、源 schema、转换版本、ID 对照和结果记录写入目标迁移历史。重复输入默认拒绝或返回已导入结果，不能重复入库。已有业务数据的目标库拒绝导入。

失效或缺失源文件可保留记录并报告；损坏关系、无法解析的版本、目标非空及不确定字段丢失为阻断项。工具不修改或删除原备份，不移动漫画，不读取凭据。

## 6. 测试与验收

使用匿名 SQLite 样本、合成图片和目录包，不默认复制生产数据。每个支持来源版本有固定测试输入及预期迁移清单。

必须覆盖中文路径、不同大小写、嵌套根目录、重复 SHA1、缺失文件、主版本切换、系列顺序、人工字段来源不明、阅读回退／完成状态、未知 schema、素材缺失、未支持字段附件、重复导入、处理中断及激活失败回退。

验收以数据类别数量、逐 ID 关系与顺序、原始信息保留清单及内容摘要为证据；不能只验证“目标数据库能打开”。真实迁移先 dry-run 和备份，再执行，不作为日常开发测试。

## 7. M0目标模型兼容性复核（2026-10-13）

当时仅审查目标数据关系设计（清理前提交`f6e40af`），尚未建立应用 schema，也未重新访问TreeC源码或生产数据。物理书籍ID/非唯一代表SHA1、来源不明的有效值、成员级收藏隐藏、独立last_read_at、系列逻辑位置及原顺序附件均有明确保留位置。

未来迁移必须保留源ID映射、输入指纹、原值附件与摘要；旧结构隐藏不转为用户隐藏，旧任务不恢复执行。M0新模型不能证明未知源版本已经兼容，转换工具仍按独立里程碑交付。M1起每次应用schema变化继续审查本表，不以本次复核代替匿名来源样本的逐类审计。

## 8. M1 schema 兼容性复核（2026-10-13）

首个实际迁移仅建立管理员、会话和 schema 账本，没有提前创建目标漫画／组织表。管理员拥有独立不透明 ID，可作为未来阅读状态归属；单账号约束不把 SHA1 引入身份。未来导入仍要求空业务目标库，已有账号如何绑定须在转换设计时明确，不能凭当前认证表宣称已支持导入。

源 TreeC 密码、凭据和旧会话不迁移；本系统会话仅保存随机令牌摘要。密码哈希允许 NULL 是未来恢复后重新设密的保留表示，M1 没有恢复 API，不能直接操作生产表实现恢复。正式恢复流程需撤销会话并通过受控初始化验证。

M1 checksummed SQL 迁移与本地升级快照不等于 TreeC 转换工具或用户备份恢复。升级快照包含原库认证摘要，保存在私有本地目录；常规备份的凭据排除、导入映射、来源附件和激活回退仍按原契约单独实现。本轮未读取 TreeC 源数据库／凭据或生产漫画。

## 9. M2 schema 兼容性复核（2026-10-13）

002_ingestion.sql 建立书库／物理书籍／页目录和最小扫描任务，独立业务 ID、library＋relative_path 唯一、非唯一代表 SHA1、内容版本及 missing／corrupt 状态与目标模型一致。源图只读，文件失效不删除记录；旧任务不会被当作来源迁移任务。

当前 title 是文件名来源的初始值，扫描更新不覆盖它；外部元数据、人工覆盖、收藏／隐藏、系列、版本和阅读字段尚未建表，不能推断已支持 TreeC 导入。logical_item 等组织锚点随对应功能建立；未发布新基线的例外见第 10 节，正式使用后的变更仍新增迁移。root_identity 仅是当前部署的安全检查，不是跨机器迁移身份。

TreeC 导入仍要求独立来源 ID 映射、明确路径重映射、来源值保留和未知字段附件，不能仅将本轮书籍表视为完成转换。运行目录从 m1 移到 dev 只调整本机路径，保留管理员／会话；它不是 TreeC 数据迁移或生产恢复工具。

## 10. 后端架构固化复核（2026-10-13）

本轮仅同步设计，源码、001／002 SQL 和 schema 2 均未变，未读取 TreeC 生产数据库或凭据。只读源码对照定位见 [后端数据架构](backend-data-architecture.md)。

- **开发期重新建库**：用户允许后续重构丢弃当前 Mac 实验库、封面、升级快照和初始化凭据；保留配置、根映射、漫画和历史测试材料。Ubuntu 不操作。此授权不扩展为 TreeC 人工数据可丢弃，也不表示本次已重置。
- **基线识别**：后续可整理未发布建库基线，新程序须识别应用／基线身份并明确拒绝旧实验库；不能静默覆盖、回退到历史目录或创建替代空库。正式使用后的同基线升级仍有版本、校验和、事务与一致性快照。
- **来源与身份**：provider＋external_id 作为来源身份；SHA1 仅为查找。旧来源字段无法判断人工或外部时保存为 legacy_unknown 的有效值，不伪造来源。
- **组织关系**：系列引用逻辑条目，版本组成员独立，迁移须同时保存源成员、原位置与主版本映射，不通过切换代表书改变系列顺序。
- **素材与派生文件**：人工素材／附件导入 assets 并保存相对引用及摘要；旧 cover_path 不能直接成为新宿主路径。自动封面和平台相关向量重建，人工选择／裁剪等不可重建信息保留为字段或附件。
- **认证与备份**：当前认证仍在主库；私有升级快照与可导出业务备份区分，后者在独立副本移除认证秘密，保留账号 ID 并重新设密。源凭据、会话及模型索引不直接导入。

本次未提供转换器、新基线、重置命令或数据兼容验收。未来目标 schema 改变时仍须逐类复核和匿名测试，不能以设计覆盖范围替代转换证据。

## 12. M3 schema 2 兼容性复核（2026-10-13）

未新增系列、版本组、阅读、素材或向量表，不提供转换器。上述类别仍按既有保留矩阵和附件约定执行，不宣称已实现兼容导入。

## 14. 管理台 schema4 增量兼容性复核（2026-10-15）
