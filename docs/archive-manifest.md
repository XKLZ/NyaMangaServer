# 页面目录、内容页摘要与多版本标签

日期：2026-10-16。foundation-v1/schema 6；006 为增量迁移，001–005 不变。保留现有数据，不清库。管理网页仍通过 Vite 5173/API 8080 使用，本轮不构建生产网页、不操作浏览器或部署环境。

## 页面目录与封面

006 先把人工选页对应的归档条目序号、解码名称及目录版本保存到 cover_selections，再删除 book_pages。books 仍保存页数、内容版本及文件摘要信息。

归档池按文件身份、大小、修改时间及编码/目录算法版本建立内存目录，只检查中央目录、筛选图片并自然排序，不整本解压。相同会话的构建串行共用结果；最多八个打开会话，空闲一分钟回收。目录单独使用32MiB保守内存预算，淘汰仅针对无使用者的会话，预算不足明确返回资源限制。失败目录不发布，取消不产生可用缓存；重启后按需重建，不增加磁盘目录缓存。

页面与图片仍经书库边界、认证、内容版本和文件身份检查。源不可用时不提供假目录；当前有效的已有封面仍可读取。人工选页通过保存的条目身份定位，新增BMP识别不会把旧选页变成另一张图。新选页由服务读取真实目录，仓储提交时复核内容版本、页数、选择revision及维护状态。

自动封面缓存键改用书籍ID、内容版本、页选择和处理版本，不再依赖元数据查找SHA1。旧摘要仅保留为旧封面缓存键的兼容信息，读取时迁入新键；文件内容变化后不再使用旧兼容键。人工封面及素材不因查找算法变化失效。

## 查找摘要与离线重算

- `first-page-v1`：历史第一页原始字节摘要。
- `content-page8-v1`：自然排序后不少于8页取第8页，否则取第1页，对原始图片字节计算SHA1。
- 目录算法为`natural-bmp-v2`，没有人工页序修改。查找摘要不证明整本文件相同，不作唯一身份。
- 封面默认第一页，与查找页独立；查找页损坏不静默回退到封面。
- 元数据任务与来源预览冻结查找摘要及算法；提交再次检查。算法更新不增加文件内容版本，不删除来源、人工覆盖或组织关系。

先正常停止当前实例，然后显式执行：

```sh
make rehash-dev
```

该命令使用`.runtime/dev/vite-config.json`及实例排他锁，拒绝缺失数据库、重置未完成状态及运行中的任务。应用自动执行006并创建升级前一致性私有快照；首次需要重算时再创建重算前快照。逐书提交，算法标识即幂等进度；中断后重复执行，已更新记录跳过。离线/损坏记录保留旧摘要及算法并进入私有报告，不创建替代数据库，不启动HTTP、扫描工作器或网络客户端。

默认报告为`.runtime/dev/data/tmp/rehash-report.json`，0600；只在Git外保存书籍ID及错误类别。账号、密码、会话、人工值和书籍编辑revision保持。运行服务仍使用：

```sh
.runtime/bin/server --config .runtime/dev/vite-config.json
npm --prefix web run dev
```

停止API对核实身份后的进程发送SIGTERM；本命令不能停止其他项目或绕过运行锁。无需为本轮执行`make build`；它会构建生产网页，与本轮热更新边界不同。

## 多标签与BMP

`version_member_labels`保存有序版本标签，每个成员最多20项，每项1–128个Unicode字符且不超过512字节。重复项去重，禁止空白项和NUL。旧非空单标签原样迁为一个元素，不猜测拆分逗号。标签归组织成员所有，独立于自动语言/颜色识别。

API增量：

| 位置 | 行为 |
|---|---|
| VersionMember | `version_labels: string[]`；旧`version_label`为首项兼容视图 |
| OrgCommand | `version_labels`整列表替换，空数组清除；`member_labels`按书籍ID用于建组/加入 |
| 兼容写入 | 新旧字段同时出现400 `conflicting_version_label_fields`；多标签时旧单值写入409 `multiple_version_labels_require_array` |
| 书籍响应 | `representative_algorithm`标明当前摘要算法 |
| 页目录/封面选择 | `directory_version`说明目录规则，页目录仍分页 |

网页多值输入保留草稿、预览和冲突流程，Enter添加，逐项移除；显示全部版本标签，不按属性自动覆盖。

BMP使用现有固定x/image依赖，接通扫描、页数、查找摘要、封面和人工上传；对外BMP预览转PNG，摘要仍取原始BMP字节。沿用10MiB上传、归档/像素/256MiB解码预算及两路图片处理。AVIF尚不支持。
