# 清理性能、终态结算与系列编号修复

## 代码行为

本轮保持schema27及001–027原字节。清理预览30分钟只约束首次确认；已接受的任务排队、暂停／恢复、执行和结算均使用原任务身份，不再被预览时间中断。每次提交仍校验权限、执行代次、当前引用、活动拥有者和文件身份。

执行每批最多64个文件；准备或写事务处理达到250ms后，在当前文件结束时提交／让出。大文件校验本身不被250ms强行中止，因此这不是硬实时期限。摘要读取、外档验证和激活记录解析在写锁之外完成，删除时再次核对文件身份；引用与登记变更、删除计数、材料收据及断点在同一写事务提交。未提交的删除若遇中断，恢复后记为“释放量未确认”，不虚报字节，也不删除后来重建的对象。

封面／标签缓存引用采用连接私有的派生索引，按本批候选键查询；本连接相关写入通过TEMP触发器失效，其他连接提交通过SQLite data_version失效。索引在同一写事务内核实／重建，不新增业务表或迁移，不再每个文件枚举全库封面。任务内冻结清单解析一次，激活记录和外档清单每批解析，检测到文件身份变化则重新验证并停止冲突批次。

结果JSON增量包含phase（deleting／finalizing／finished）、status（running／completed／partial／failed／finalization_failed）、error_code、unconfirmed_files以及批次／候选引用查询计数。任务终态与结果在同一事务结算。旧结果缺少字段时网页结合任务状态和计数兼容展示；“删除已完成，任务收尾失败”不能显示成仍有文件待删除。

## 已删除任务的离线纠正

`cleanup-reconcile`必须在目标API正常停止后运行，使用实例排他锁；默认只预览，不调用删除。运行前核对任务ID，不以界面100%作为依据。

```sh
# 在项目固定Go环境中构建到本次独立工具目录，不覆盖旧恢复配对程序
 go build -o .runtime/bin/cleanup-reconcile ./cmd/cleanup-reconcile
.runtime/bin/cleanup-reconcile --config .runtime/dev/vite-config.json --job TASK_ID
# 仅上一步证明全部条件满足时
.runtime/bin/cleanup-reconcile --config .runtime/dev/vite-config.json --job TASK_ID --apply
```

限定为已终止、preview_expired、一个完整处理成员的清理任务；要求冻结条目、删除计数、字节数、全部材料收据一致，无跳过／删除失败或活动执行。检查schema与账本，不启动普通迁移或后台恢复。修改任务及成员终态，保存原状态、原错误、原代次、纠正时间及证据摘要；重复运行幂等。已释放空间不增加，后来生成的`.DS_Store`等文件不读取或删除。不满足条件即拒绝，不能拿此工具纠正其他失败。

## 系列编号

健康规则版本升至2。连续但起点不为1显示“系列编号起点不符合规则”（series_positions_start）；真正不连续仍为series_positions_gap。新结果含系列名称、实际／预期起点及成员数，完整ID在详情中保留。历史报告不改写。

修复继续使用series_positions白名单动作，仅将当前顺序编号为1…N。单批全部为此动作时允许最多1000项，其余修复仍最多100项。每次修复只有一份一致性快照，保持成员、首选及相对顺序；有后续变更时按原指纹拒绝执行。取消、故障、回退继续使用[健康修复](data-health.md)的维护屏障和版本保护。

独立TreeC工具已串行修正规则和验证：系列位置从1开始，页码／标签等原0起点不变；规则版本与检查点身份同步更新。只完成匿名转换和标准恢复，旧真实恢复包、转换档案均不改写。


## 验证范围

匿名测试覆盖跨预览期限的执行、批次中断、文件替换、引用冲突及系列位置修正。私人任务纠正记录不随源码发行。性能与新版本的实际结果以相应发行验证为准。
