## 检查范围与结果

| 模式 | 检查内容 | 源漫画访问 |
|---|---|---|
| quick | 有期限的只读事务：应用身份、迁移checksum、quick_check、外键、表／索引／约束和核心组织关系 | 不读 |
| application（默认） | 完整数据库校验、来源／人工覆盖与有效字段、标签／属性／语言／搜索投影、人工图片、缓存／译库／推荐引用及任务检查点 | 不读 |
| sources | 应用检查，加显式选定书库的文件身份、归档目录、全部受支持图片条目的CRC及解码 | 单并发，停用书库跳过 |

完整数据库校验使用SQLite Online Backup逐页复制到私有一致性临时快照，包含已提交WAL，并保留原索引页供integrity_check诊断；不通过VACUUM重建索引来掩盖原索引异常。目标文件先以0600创建，检查后删除；中断可安全重建检查用快照，不覆盖修复回退点。检查只写自身任务与报告，不改业务资料。

检查开始时在事务中冻结Edition、Work、Series、素材、派生引用的目标、指纹和对象revision，按稳定ID分批处理。新增对象不属于该检测时点范围；删除或改变的目标报告过期。源身份包含文件路径、内容版本、摘要算法及书库根映射／根身份／编码／启停／revision。收藏等非目标资料不会让整份报告统一过期。结果筛选、动态过期判断、计数和分页在SQL完成。

来源、人工覆盖与有效投影分别核对，不使用模型判断人工匹配是否正确。Work首选必须属于自身，系列位置从1开始；压紧保留相对顺序。图片核对原始引用、摘要、大小、尺寸、格式及解码。译库从已有校验通过的原始缓存解析，流式比较派生条目及规范化字段；不联网。推荐特征核对版本、指纹、摘要及载荷形状；系列压缩块限8MiB、解压限16MiB、最多512条信号，并核对gzip CRC和记录数；Work配对位图核对长度及填充位。任务检查覆盖活动输入JSON、代次／资源归属、导入阶段、方案成员和检查点边界，历史失败或用户暂停本身不是异常。

状态为normal、confirmed、inaccessible、manual、not_checked、stale。未上传图片、未匹配来源、未归系列、关闭功能未配置资源和正常缓存淘汰不算损坏。仍被有效代次引用而丢失的压缩检查点单独报告；不自动推理重建。编码未识别、危险目录名和未知验证错误不会直接判为文件损坏。

报告包含规则版本、检测时点、冻结目标数、问题分类计数、检查点、对象版本与逻辑读取量。`source_bytes_read`是深检累计尝试的未压缩图片载荷字节，不是物理磁盘计量；失败的图片尝试也计入预算。`max_bytes`只控制该深检预算，默认8GiB、最多1TiB，不放宽原归档／图片上限，也不限制数据库、目录和应用素材IO。超限记not_checked，不作损坏结论。GIF等格式沿用正常阅读的首帧解码规则。

完成度incomplete、checked_scope、limited只描述请求范围。有未检查、过期或不可访问项时不能显示全部健康；任务失败不等于问题为零。没有历史整本摘要时，不声称文件从未变化。报告是检测时点证据，不是持续扫盘监视；宿主源文件后续变化需重新检查。

## 修复预览、屏障与回退

只允许以下动作：

| 动作 | 依据与保护 |
|---|---|
| projection | 从完整来源、人工覆盖和文件名回退重建有效字段／标签／属性／语言／搜索；保留人工值、版本标签与决定 |
| tag_evidence | 重建派生原作／角色证据，保留全局人工决定及逐本否决；与同目标projection合并 |
| cover_cache、tag_cache | 原始素材或显式允许的源图片可用；预览验证输入，保留原始素材及选择。选页封面使用保存的条目ordinal和名称，不按旧显示页码选图；content_changed拒绝 |
| dictionary | 只从已有、摘要及解析校验通过的原始缓存离线恢复，保留人工译名 |
| preferred | 唯一成员自动给出确定选择；多成员必须明确指定自身成员 |
| series_positions | 保持相对顺序，压紧为1、2、3…… |
| quarantine_recommendation | 隔离确认无效的派生文件并保留旧字节，不修改推荐决定，不启动模型 |

不删除孤立业务记录、不补造File身份、不猜测组织或替换来源。数据库身份、迁移、完整性或预期结构异常阻止普通修复。缺失或受损的原始人工素材不能凭空恢复，只报告重新上传／后续恢复依据。

计划固定目标指纹、选择、暂停任务数量、空间估计及30分钟有效期。检查／预览过期返回409；同幂等请求身份返回原检查、计划或执行结果，新身份仍需重新校验。空间估计包含一份数据库快照、事务余量、目标旧文件及暂存余量，不按每个目标复制整库。

执行先持久化全局维护状态，暂停排队和运行任务并提升代次；原先暂停者保持。HTTP门禁在会话、Origin和CSRF之后执行，普通业务写返回503；只读搜索、报告、登录／退出与精确修复控制通路保留，Bearer只读查询不变。Store的每个受控写连接安装TEMP写入屏障，业务最终提交和任务领取也受保护；私有修复权限只在排他连接租约内启用并验证复位。任务工作器、上传、cache-miss GET、后台缓存与cleanup的IO租约必须收尾后才建立修复材料。已有封面、标签图及导入预览可只读读取缓存；维护期间缺缓存不会生成或下载。

每次修复只建立**一份**0600一致性数据库快照和必要旧文件；目标逆操作与独立文件日志逐项记录。数据库动作事务化，文件先暂存、校验再原子发布，旧字节保留。文件切换、SQL收据、完成收据和解锁均核对任务代次；旧工作器不能暂停新代次、覆盖其进度或解除屏障。每项完成后复查，故障停止后续项，结果区分verified、failed、pending；回退文件未完成时详情显示rollback_pending和文件检查点。

回退只恢复目标Edition、Work或Series的相关行及目标文件，验证修复后的指纹，不替换打开中的app.sqlite。共享tags只补回必要旧ID；人工覆盖、决定、人工译名及无关目标的后续编辑保留。后续目标编辑导致409并保留维护保护。已损坏首选引用的显式逆操作只在该排他连接临时停用FK检查以恢复原值，释放连接前强制恢复FK或丢弃连接；其他业务写仍受保护。回退恢复的是操作前状态，可能重新出现原检查问题，不能当作健康证明。

重启时排队／运行中的修复也转暂停，不自动继续或解锁。继续复用原job的resume；取消仍保留保护，可明确继续或回退。正常完成或回退后，被维护暂停的业务任务由用户主动恢复。结束窗口使用有期限的独立收尾上下文，并在最终事务再次验证同一代次与终态，既防自身watcher取消造成finishing残留，也拒绝旧代次释放新进度。

权限复位失败会丢弃连接并持久保护。`health-write-unsafe`不是启动时盲删：有修复时，复核已完成收据后受控清除；无修复owner时，recover入口等待IO、校验数据库与连接权限、暂停活动任务后清除。未知条件或校验失败保持保护。材料纳入health_rollback存储统计；既有清理预览及执行均保留健康报告／修复／暂停任务引用，不能删除活动或必要回退点。

目录和派生版本随修复／回退失效；Work沿既有work_catalog_update触发通知，Series和关系／译库补充相应通知。新增health_check、health_state、health_repair事件只提示重新读取，不提升客户端草稿提交版本。

## HTTP契约

均位于`/api/v1/maintenance`，沿用会话、Origin、CSRF、分页与SSE，不改变容器live／ready语义。完整字段以[OpenAPI](../api/openapi.yaml)为准。

| 接口 | 用途 |
|---|---|
| POST／GET health-checks | 创建202（id、job_id）／分页历史 |
| GET health-checks/{check} | 进度、计数、冻结范围与完成度 |
| GET health-checks/{check}/findings | status／category筛选及服务端分页 |
| POST health-repair-plans | 选定finding_ids、preferred_editions、allow_sources，返回影响预览 |
| GET health-repair-plans/{plan} | 冻结计划 |
| POST health-repair-plans/{plan}/execute | request_key、expected_revision、confirm_maintenance=true，返回202及持久job_id |
| GET health-repairs/{repair} | 状态、操作方向、逐项收据、文件日志状态、被暂停任务 |
| POST health-repairs/{repair}/rollback | 同样明确确认与revision，返回202 |
| GET health-state | 全局保护、owner及继续／回退入口状态 |
| POST health-state/recover | 仅无修复owner的异常权限保护恢复，不能绕过活动修复 |

检查和修复暂停／取消／继续复用既有job控制；独立修复方向和检查点保留。请求、报告及日志使用稳定脱敏错误类别，不输出宿主路径、源标题或凭据。

### 使用与保护

- 默认“应用数据检查”，另有快速检查和显式选择书库的源文件深检。深检默认8 GiB、最高1 TiB，说明其为未压缩图片载荷尝试预算，不冒充物理磁盘IO计量。不自动选择全部书库或读取源漫画。
- 桌面为240px分页历史与报告；手机默认收起历史，先呈现报告。报告默认筛选确认异常，保留全部六种结果计数、分类筛选、服务端分页及冻结范围。检测时点、实际阶段、已产生的结果条数和覆盖限制独立显示，结果条数不是完成百分比。失败、取消、不可访问或有限范围不显示“全库健康”。
- 只允许选定确认异常中的白名单项，最多100项；跨页选择保留完整条目，整页加入超过上限时整次拒绝，不截断选择。按检查分别保留选择、首选版本和源读取授权；刷新、SSE、成功启动另一检查或执行另一修复均不清除其他检查的草稿。
- 多版本作品必须在其自身版本中明确选择主版本，服务端每页25项；单成员作品可由服务端确定。重建封面需另行允许读取来源。修复先生成冻结影响计划，再一次确认维护；显示单份一致性快照、空间、全局只读、暂停任务、目标及回退影响。执行使用计划revision和固定请求键；过期409不能直接重试，选择保留并要求重新检查。其他阻塞错误保留真实错误，不统称结果过期。
- 检查和修复沿用持久maintenance任务，支持既有暂停／取消／继续；维护任务历史由服务端分页，选中后才读取对应检查或修复，避免逐行额外读取。只有检查与修复均明确404才归为其他维护任务，读取失败保留错误和重试。check、repair、筛选和分页保存在URL，稍后可重新进入完成的修复并核对回退。
- 全局状态独立于活动页签。维护期间普通业务写、原始PUT及上传在请求前被阻止，浏览、只读搜索和标签联想仍可用，字段草稿保留。状态读取失败保留既有保护；已知23但尚未读到状态时不放开写入。健康控制使用明确路径及对应任务身份，不使用前缀通配放行。
- 继续维护仅对当前owner且任务确实停止时提供；其他owner不能控制历史修复。正常完成且全局空闲的修复允许明确回退，不因状态空闲时can_rollback=false而丢失入口。回退遇到后续目标人工编辑会暂停并保留保护，不覆盖编辑；无owner的异常保护走独立核对恢复入口。被维护暂停的业务任务不自动恢复。
- 活动状态轮询随页面可见性暂停，终态停止；SSE只触发重新读取，200ms合并突发事件、单一在途读取及一次后续刷新，旧代次结果不能覆盖新状态。通知和刷新不提升任何编辑草稿或计划的起始版本。
