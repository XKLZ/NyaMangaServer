## schema11与标签保护

011新增四张表，总计66张应用表。001–010保持原字节与校验和，不清库。

| 表 | 用途 |
|---|---|
| `edition_label_policy` | legacy／auto／manual维护状态、策略revision、规则版本与待核对标志 |
| `edition_automatic_labels` | 有序预设标签，与已有人工字符串分开 |
| `discovery_feature_inputs` | Edition稳定身份对应的已验证特征输入登记 |
| `discovery_run_features` | 各发现任务的匹配输入指纹；不依赖旧行号 |

`work_discovery_runs`另增执行版本、基线引用及复用／计算统计。升级把历史非空字符串标为manual，空值标为legacy；**不生成或改写历史标签**。人工与自动相同文字仍保持不同来源，不猜测人工文字是预设。

自动规则现为 `edition-preset-labels-evidence-v2`：原版、译本、无修、修正、彩色、黑白、DL、特别。每个维度保留可靠证据，不再因语言不同、共同属性或对方未知而省略；DL仅认明确电子发行标记，不因来自下载或画廊而推断。缺失不能反推相反值，人工明确未知和自动冲突不回填；不再自动生成“其他”。多版本组完全没有可靠建议时不改任何现有标签；单版本Work不保留组内区分用自动标签。升级不批量改写旧资料，旧自动“其他”仅在主动生成得到可靠结果后替换。详见[本次修复](discovery-label-fixes.md)。

成组、加入、移归、拆分、永久清除及撤销在组织事务内刷新受影响Work的自动标签；属性投影更新也维护已激活的自动标签。未改变成员的历史legacy组不因打开网页或升级而批量激活。人工模式及明确空数组始终受保护。恢复自动为显式操作，仍保留人工自定义字符串；如需删除人工文字应明确编辑。

组织内部快照仅保存人工字符串，公开成员响应另合并自动标签及来源，避免撤销／组织持久化把自动值误登记为人工值。自动刷新不会改写元数据或推荐输入。

## 增量执行与限制

执行版本为 `work-discovery-incremental-v1`，配对证据仍使用原评分与证据版本。

1. 任务冻结当前输入，在同书库已完成／失败／取消且执行、证据、算法版本一致的任务中，优先选择已提交行数最多的基线，同等覆盖再选最新。每对复用仍检查稳定身份与特征指纹；不完整行不能复用。没有可验证指纹的旧任务不强行转换；首次新版任务或明确完整重算会补建基线，但仍可复用模型特征缓存。
2. 有效注册素材以稳定Edition ID、素材摘要／大小／时间、内容版本和题名登记输入；验证特征缓存的模型身份、输入摘要、向量／pHash和内容摘要。缓存缺失／损坏则单本重新准备。普通源归档没有可靠素材身份时，仍安全读取并核对所选图片字节，随后复用模型特征缓存，不能声称完全不读源文件。
3. 旧基线按稳定Edition ID映射。未变化对象复用推荐边、硬冲突及完整已比较覆盖；压缩行块记录未达门槛结果，不把不存在的记录当作已比较。新增／变化对象仅计算相关配对。
4. 当前任务写出自己的完整压缩检查点，完成后可独立成为下一基线；运行时旧基线受外键与清理保护，复制完成才释放依赖。暂停／重启重用检查点，取消和代次校验拒绝陈旧写入。中断后特征变化会原子清除依赖行并重置进度，重新计算。
5. 只改组织、主版本或版本标签时，匹配指纹不变，可直接重建组织方案。生成方案仍检查当前约束、忽略决定及revision。

“无重新配对”不等于零耗时：仍需冻结输入、校验缓存、映射证据、复制压缩行块及重新生成方案。目前复用的是选定完整或部分检查点，不是无限历史证据库；已有任务与旧执行版本按旧语义恢复。取消任务可保留对旧基线的保护直到历史任务被清理，以安全优先。

## API增量

所有接口位于 `/api/v1`，沿用认证、Origin、CSRF及稳定错误响应，详见 [OpenAPI](../api/openapi.yaml)。

| 接口 | 增量 |
|---|---|
| `GET /works` | `min_editions`筛选；封面／内容版本；同一读快照计数和分页 |
| `GET /works/{id}/editions` | 批量返回语言、属性、主版本、封面版本及`label_state`，避免逐本详情请求 |
| `POST /works/{id}/version-labels` | 带`expected_revisions`生成标签；`restore_edition_ids`显式恢复自动 |
| `GET /work-proposals` | `target_work_id`配合`alternatives=true`获取目标组全部有效加入方案 |
| `POST /work-discovery-jobs` | 默认增量；可选`full_recompute` |
| `GET /work-discovery-jobs/{id}` | 阶段、基线状态、资料登记／特征缓存／实际推理／配对复用统计及脱敏失败位置 |

旧字符串数组接口仍是人工编辑。`label_state.items`分别返回manual／automatic及稳定预设ID；清空字符串数组同样保护，不在下次自动刷新时悄悄补回。推荐采纳与自动标签在同一事务提交。
