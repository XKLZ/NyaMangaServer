# 完整导入流程

本阶段在 `foundation-v1` 上增量实现导入编排。普通扫描仍离线。
完整导入由用户明确授权联网：扫描 → 候选元数据 → 元数据整批审核 → 版本审核 → 系列审核 → 完成。
每一关的采纳／不采用均由用户决定；最后一次明确处理成功后可自动推进，初次打开或刷新不触发推进。无结果提供明确继续入口，不代表获取成功。

## 数据与恢复

012 新增批次、固定扫描成员、子任务预留／关联、候选和审核记录。
子任务 ID 先持久预留，实际创建任务的事务同时建立关联，重启不重复创建。
扫描写索引的事务同步记录新增与内容变化；未变化的旧条目不获取元数据。
导入元数据存入独立候选，分类、评分和标签仍完整保存；采纳前不改变正式来源。
候选不采用单本预览的30分钟期限。采纳校验内容、查找摘要、来源选择和候选版本，重新应用最新人工覆盖。
暂停／取消保留已提交索引和已采纳结果，不作全批回滚。

## 操作指南

1. 进入“书库”，在对应行点击“导入漫画”，直接建立批次并进入扫描。该按钮提示流程将联网匹配元数据；索引仍只读源文件，联网仅限本批新增／内容变化成员。
2. 有未结束批次时显示“继续导入”，只打开原批次。历史入口 `/admin/imports` 支持书库、状态和分页筛选，保留 `?batch=` 深链接；仅更新文件索引位于书库“更多 → 高级维护”，与周期扫描一样保持离线。
3. 元数据审核突出完整文件名、匹配标题和真实画廊网址。复制文件名包含扩展名，不包含绝对路径。可手动填写网址，或点击“粘贴并重新获取”；浏览器拒绝剪贴板时保留手动输入方式。
4. 修改网址不采纳来源。新获取失败时，旧候选及旧网址保留；未获取的网址草稿阻止按新网址采纳旧结果。分类、评分、标签等完整候选可展开查看，共享来源影响单独提示。
5. 勾选确认匹配、人工补充，或选择本次不更新元数据。可跨页勾选，最多1000项；批量冲突整体回滚。损坏源文件修复后，可只重试本批失败文件，不纳入后来出现的文件。
6. 版本阶段使用建议列表和单方案审核。可直接排除新增成员，再组成／加入版本组或不采用；无关作品保持现状，不需要逐本确认。
7. 系列阶段按版本确认后的真实Work去重，可直接修改新系列名称、成员和顺序。采纳／不采用最后一条主建议后，待任务和后台重验结束再自动完成。没有建议时点击继续；已有系列不重复占位。旧成员审核接口保留兼容，但新界面不逐本确认。

取消只停止本批持有的任务，保留已入库、采纳和组织结果。暂停、取消使旧工作器代次失效；恢复等待原工作器释放所有权。人工等待不占用工作器。
审核后的相关输入变化返回冲突；“重新审核／处理输入冲突”保留已采纳资料，停止本批未完成子任务并回到元数据审核，不自动再次联网。过期候选需要重新获取，或明确保留当前资料。

网址草稿、选择及系列编辑草稿保留在当前浏览器标签页的sessionStorage，关闭标签页后由浏览器清理；不保存Cookie、凭据或原始来源响应。任务和决定在服务端持久保存，换浏览器可继续审核。

## 接口与存储

- `/api/v1/import-batches`：显式网络授权、幂等创建键、分页批次与详情。
- `/{id}/members`、`/{id}/members/{edition}/candidate`：服务端分页的当前阶段成员、完整规范化候选；不返回远端原文。
- `/{id}/reviews`：冻结成员revision与候选revision的原子批量审核。
- `/{id}/members/{edition}/refetch`、`/{id}/retry-files`：重新获取、冻结失败文件的局部扫描重试。
- `/{id}/work-proposals`、`/{id}/series-proposals`及相应操作：批次独立方案、原有组织事务与撤销快照。
- `/{id}/organization-review`与`/{id}/organization-review/complete`：同快照建议门禁、后台重验及原子阶段收尾；备选只作废不记人工否定。
- `/{id}/control/{action}`：继续、暂停、恢复、取消、失败阶段重试、重新审核。
- `/api/v1/jobs/{id}/import-batch`：任务中心返回所属批次。
- `/api/v1/series-discovery-jobs/{id}`：实际新增与复用配对计数、压缩空间和基线状态。

012增加8张编排表；013增加3张派生检查点表，最终schema13共77张应用表。001–011不变。批次与任务不是同一实体，子任务`parent_job_id`不指向批次ID。扫描发布及成员记录同事务，元数据工作器在远端IO前和提交时都验证批次所有权及请求代次。

## 系列增量与资源边界

保持冻结的评分、门槛、聚类、命名和排序规则。Work指纹包含实际解析画像、全部Edition题名／创作者／成员及规范化向量，故全库别名变化可使旧Work指纹失效。版本标签不参与匹配。Work匹配也将实际解析后的指纹加入配对复用身份。

召回仍针对当前完整Work集合检查三路top50；新成员可能改变旧成员的召回名单。保存实际调用过的正／负／冲突信号，聚类跨组检查缺记录时按需评分。没有记录不代表已比较或未命中。

压缩块保存在`data/indexes/recommendations/series/<分片>/<SHA256>.json.gz`，数据库保存相对键、摘要、字节数、输入画像和进度。单代次128MiB限额；512条信号为一块，带校验及解压上限。保留当前、上一完整及构建中代次，引用基线的任务通过外键保护；完成后清理仅限该派生目录内无引用的内容寻址块。

损坏／丢失块降级重算相关信号，不阻断普通业务；旧schema没有可验证基线时首次补建。相同输入重复查找可无新增模型推理／配对评分，但仍有输入校验、召回检查、聚类及方案事务开销。Mac测试不代表NAS性能。

### 已扫描与已导入的区分

`file_import_state`按Edition保存已明确处置的内容版本。012升级时将已有文件设为保存的旧库基线，不重新获取已有资料；之后普通／周期扫描新入库的文件没有导入处置记录，因此下一批仍会纳入。内容版本变化同理。
元数据关卡的明确采纳／保留／人工补充／暂不补充更新处置记录。取消批次不回滚资料；尚未处置的成员仍可在下一批进入，避免“已经扫描过，所以永远跳过”。已明确处置但后来取消后续整理的条目保留现状，可使用独立版本／系列工作台继续整理。

后续审核工作台的展示与原子人工编辑契约见[导入审核工作台](import-review-ux.md)，本页此前截图与浏览器证据对应旧版界面。
