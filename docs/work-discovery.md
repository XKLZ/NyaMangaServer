# 同作品发现与快速整理

> 本文保留schema9实现历史；当前入口、自动成员重验和跨任务增量复用已由[schema11版本管理](version-management.md)更新。历史全库重算描述不代表新版每次查找都重算全部配对，旧任务仍按旧语义恢复。

本轮基于`codex/work-recommendation-pilot / 099a81a`继续实施。目标是选择书库后生成“组成作品／加入已有作品”方案，由用户一键确认或忽略，并可撤销。本文件记录当前增量，不能把后端检查视为网页或真实推荐质量验收。

## 第一增量：后端与契约

`jobs.mode=library`明确区分全库发现与旧单本／批量查询。任务在服务端冻结整个启用、未回收书库的符合条件Edition，不受1000个指定ID限制；同书库最多一个活动或暂停发现任务。暂停／取消递增代次，旧结果不能提交或释放新资源。整库重试建立新任务并保留父任务，拒绝成员序号重试。

Python运行组件每次准备整个池一次、解析标题一次；随后仅传池身份和行号，计算上三角分块，每个无序配对一次。最终候选及临界分数用原canonical点积复核，不改变固定V4阈值。复用既有特征，不新增模型、不调参、不联网。恢复时复用持久行检查点；进程重启可能重新加载缓存、准备池，但不会重算已提交配对。

资源预算明确失败而不截断：最多2000万比较、25万候选边、128MiB证据JSON、10万个方案及有界极大团搜索；既有32MiB消息和2GiB worker软预算继续生效。硬冲突按位保存，包括未达到推荐门槛的成员对。方案计算在只读快照提交之后、写事务之前进行；发布用短事务复核输入和代次。

## 方案规则

- 组成作品要求所有新增成员两两达到候选门槛。AB与BC达标、AC未达标时保留AB与BC局部方案，不连锁组成ABC。
- 加入已有作品参考所有目标版本，以最佳支持版本判层级；其他版本低相似不等于明确冲突。任何目标成员的明确内容冲突均提示核对。目标容量及singleton身份按真实全部Edition计算，包括回收成员，个人隐藏不改变类型。
- 一个Edition默认只占一个主方案；替代方案分页读取。两个已有多版本Work不会自动拆分或合并。跨系列冲突阻止一键采纳。
- 组成默认保留最早入库Work身份、名称和首选，系列规则沿用领域变换。加入只移动singleton Edition，保留目标系列；元数据、人工标签、收藏、隐藏和文件不改。
- 用户排除成员后先resolve更新可见方案，尤其不能在采纳时静默换保留Work。resolve和accept必须显式传非空、无重复的member_ids；组成至少两本，加入至少一本，只能排除新增成员。
- 忽略以方案语义输入键持久保存；目标完整成员集合和实际输入参与键，不把整组忽略解释为每条配对的负例。任务清理不会删除忽略决策或撤销快照。
- 采纳和决策同事务，重复采纳幂等。采纳后持久标记后台重组，复用配对证据，不在点击事务内重算全库。重复发现不叠加同方案；无关方案revision和已resolve的成员选择保持有效。
- 撤销只恢复实际改变的组织身份、成员、名称设置、首选和系列位置，revision单调增长。相关组织后续编辑返回冲突；普通元数据／收藏变化不阻止，也不被覆盖。没有改变的系列不会被回写、升版本或撤销新名称。

## API增量

| API | 语义 |
|---|---|
| POST /work-discovery-jobs | 冻结书库，返回202和任务ID |
| GET /work-proposals | 书库／任务／类型／状态筛选及分页，默认主方案 |
| GET /work-proposals/{id} | 完整可见成员、保留目标、影响和revision |
| GET /work-proposals/{id}/alternatives | 有共享新增成员的替代方案，真实分页 |
| POST /work-proposals/{id}/resolve | 验证成员排除，返回更新目标的子方案 |
| POST /work-proposals/{id}/accept | 仅接受revision和显式成员，不接受客户端组织命令 |
| POST /work-proposals/{id}/dismiss、restore、undo | 忽略、恢复建议、撤销新采纳 |

全部位于`/api/v1`，沿用认证、Origin和CSRF。未知方案返回JSON404，陈旧输入410或组织／版本冲突409。能力接口新增明确的`discovery`和`proposals`标志，旧后端的`enabled:true`不代表支持新流程。旧评测API历史保留，第二增量将替换网页主流程。

## 使用步骤

1. 打开隔离试用管理页`http://127.0.0.1:5174/admin/recommendations`，选择书库并点击“查找同作品”。任务只在这次点击后启动，可暂停、恢复或取消。
2. 在“组成作品／加入已有作品”核对全部成员、保留作品和风险。“建议整理”仍需用户判断；“需要核对”保留补充候选，不能当作已确认关系。
3. 无需排除时直接组成／加入。排除新成员后先更新成员方案，查看新的保留作品，再采纳；已有目标版本不会被排除或拆分。
4. 不合适的完整方案可以忽略，之后从“已忽略”恢复。新采纳可在卡片或“已整理／可撤销”撤销；后续相关组织编辑会阻止旧撤销，不覆盖新整理。
5. 后台复用配对证据更新其他方案。已有列表和成员选择保持，提示更新时可显式加载；初次空列表自动展示。普通属性与预设标签仅作核对，不自动写版本标签。

启动命令沿用`make pilot-api`和`make pilot-web`，分别Ctrl-C正常停止各自进程。当前Codex启动的真实试用服务由主Agent协调，不用以上命令重复占端口。这里不接入扫描／元数据自动导入链或系列推荐。
