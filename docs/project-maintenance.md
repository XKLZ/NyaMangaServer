# 项目维护

## 本地实例

先用 `make status-dev` 检查身份。正常启停使用 `make dev-api`、`make dev-web`、`make stop-dev`，不强杀、不并行打开两个后端。

代码修改不授权操作业务数据。升级前确认任务、导入编排、修复及恢复状态；保留应用的一致性快照。不要复制活跃 WAL 数据库，也不要通过独立 SQL 绕过实例锁。

## 数据保护

`.runtime/dev` 可能包含真实资料；`.runtime/tests` 才用于匿名验证。不要递归清理整个 `.runtime`，不要把当前恢复、回退材料及配对程序当作缓存。

应用清理使用维护预览与引用校验。整实例恢复需要匹配程序，详见[备份恢复](backup-restore.md)。源漫画始终只读。

## 发布与历史

公开仓库从经过审查的首发快照开始；私人开发历史只保留在维护者本地，不作为公共分支发布。
发布执行规则见[发布流程](releases/PROCESS.md)，发行版本的验证范围见[测试版说明](releases/v0.7.0-beta.1.md)。
