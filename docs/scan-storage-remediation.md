# 扫描、解析与存储管理

## 迁移和扫描契约

### 取消迁移默认待复核

独立转换工具将TreeC明确存在的文件转换为available，不再统一写needs_review或treec_unverified_directory；明确缺失保留missing，真实异常给具体原因。未关联源根由书库映射状态表达，不批量降级文件。正常恢复仍stat核对路径、类型、大小，无需先扫描全库才可使用。未完整验证每页只属于检查覆盖，不是使用门禁。摘要算法身份保持真实，需要新算法时按相应操作准备，不阻止已有资料／封面浏览。仅修正规则及匿名测试，不改旧包身份、不重新转换本次真实数据。

### 读取、预算、编码和结果

- 安全识别并排除macOS系统附属项，不能按所有隐藏文件一概过滤，也不能绕过越界、符号链接等检查。
- 代表页SHA1有界流式读取原始字节，检查长度与ZIP校验，不完整解码；摘要成功不等于每页完整解码通过。
- 正式应用图片消费者共享512 MiB预算，不是每个Pool各自512 MiB。保留像素、解压大小和既有并发限制；错误区分条目数、单页字节、像素及估算解码预算，返回阶段、actual和limit，不带源路径或原始异常。
- 新增027，001–026字节和checksum保持。持久保存单文件编码覆盖、解析版本和结构化扫描问题；不改变源数据或旧任务历史。
- 单文件编码默认继承书库，可选择utf8／gb18030／shift_jis；只读预览部分解析结果，多个候选有效时要求明确选择，不替一本漫画更改整库。
- 解析变化更新页目录／缓存／冻结输入身份，不伪造文件内容版本变化；保留阅读状态和人工页码封面，页序变化时标记待核对，不静默套用旧页码。
- 新结果区分已完成、已入库但部分处理未完成、无法完成文件检查。兼容旧任务state，增量返回分类／警告数与多阶段问题，避免最后一个错误覆盖前序错误。编码和资源限制不直接等同损坏。
- 定向重试只处理未完成步骤，原成功阶段不重跑。旧任务失败记录不改写，新尝试绑定原输入与当前版本，旧工作器不能发布。

### 封面复用

已有素材／指定页封面时扫描不生成额外首页缩略图；默认首页缓存有效时不重新解码或写入。缓存身份覆盖实际输入与处理版本，扫描不改变人工封面。当前无用途首页缓存列为清理候选；备份的人工选择不能被默认首页替代。

## 存储分类与生命周期

四类：长期资料（资料库、漫画封面、标签主体／背景、已安装译库、用户备份）；可重建缓存（封面／标签展示、候选预览、推荐特征及比较）；任务临时文件（上传、处理、失败的非必要工作文件）；恢复与回退材料（恢复工作副本、校验／激活暂存、升级快照、健康回退）。

- 保留稳定内部kind及旧响应兼容，网页全中文，技术标识只在详情。未知项显示其他应用数据、默认不可删。
- 返回总占用、可清理／受保护占用与原因、统计时间和关联操作。无嵌套重复计数；源漫画不计入。统计分批、不因轮询反复全量走盘，秘密内容不返回。
- 清理建议默认选择过期／冗余缓存及已结束无用材料，不默认清空有效缓存。用户备份与恢复上传工作副本严格区分。
- 已完成／失败／取消的材料按实际可续做／回退用途分类，活动、待激活、未完成修复和被引用文件保持保护。有新业务写入导致回退不可用时，不再无期限保护无用大文件。
- 清理仍有效回退点的影响在同一个确认面板说明；保留精简收据、终态日志，持久标记材料已清理，后续启动与历史读取正常，回退明确不可用。
- 最近一次可用升级快照默认保留，其他可选；有效缓存全部清空为次级操作，明确重建代价。
- 复用维护预览、执行任务和冻结清单，不为删除暂存再复制整实例；执行复核引用、活动操作、文件身份。中断可续做，不删除新建替换对象，不递归清空整个instance-recovery。
- 旧离线失败预览未必有主库操作记录，需通过经过验证的离线收据／清单识别；未知状态不可直接删，不能伪造已完成身份以绕过保护。

### 迁移原图核验与清理

提供受控离线命令，只读核验用户指定的转换档案及3,308份原图的摘要与存在性，生成绑定档案和素材身份的私有核验记录。不得让网页读任意宿主路径。清理时重新验证档案未变和素材无新引用，再删除实例无引用副本及登记；正式封面、标签图片和外部档案保留。未核验的treec-originals不可被通用孤儿清理绕过。

## 027后端接口与离线核验交接

### 解析与扫描

`GET /api/v1/editions/{id}/encoding-preview`（兼容books别名）要求该库编辑权限，返回`revision/content_revision/parsing_revision/inherited_encoding/candidates/requires_choice`。候选包含`encoding/valid/page_count/directory_digest/sample/error_code`，每个候选最多8个页名。多个候选有效时只展示，不自动选择。

`PUT /api/v1/editions/{id}/encoding`（同样支持books别名）示例：

```json
{"expected_revision":3,"content_revision":1,"parsing_revision":1,"encoding":"shift_jis","directory_digest":"预览返回的摘要"}
```

`encoding:null`恢复继承书库；摘要、Edition版本、内容版本和页序代次均须匹配。重复设置同一有效输入为无修改返回。目录摘要描述按自然顺序排列的物理ZIP成员索引；等价编码及v2→v3后仍相同的页序不会增加`parsing_revision`，内容版本不会因解析变化增加。旧v2首次解析时比较新旧成员顺序，只在真实顺序／成员变化或无法证明旧顺序时增加代次。只读页目录／页图若发现旧记录的真实顺序已经改变，先返回parsing_changed，等待明确扫描或编码选择持久化新输入，不把旧页码直接套到新顺序。合法`._`图片保留，`._`仅在26字节头满足AppleDouble magic及版本时排除；`__MACOSX`、`.DS_Store`在路径与符号链接验证后排除。

页序变化保留原阅读页码、完成状态和人工页码封面记录，返回`reading_state.parsing_stale`／`cover_selection.state=parsing_changed`。阅读写入和会话启动附带当前`parsing_revision`，确认旧位置失效时发送`accept_parsing_change:true`；页码封面重新选定也附带当前代次。普通页目录和原始页图接口支持`?parsing_revision=N`，代次大于1时不可省略；旧代次或响应过程中输入改变返回409 `parsing_changed`。代次1的旧请求保持兼容，素材封面不因编码变化失效。

文件响应的`file`内增量返回`encoding_override/parsing_revision/parser_version/directory_digest/effective_encoding`。扫描item新增`scan_result`：`classification=completed|partial|blocked`，`stages.directory/cover/lookup`和`issues[]`。问题保留阶段、兼容错误码及可选`resource/actual/limit`；Job新增`scan_completed/scan_partial/scan_blocked/scan_warning_count`。例如已入库但封面受预算限制时，旧item仍可为failed，而新分类为partial、文件仍available；SHA1成功独立保留。限制诊断也出现在HTTP `error.details`，不含宿主路径。

定向重试沿用原接口及原失败历史，固定输入不符则冲突；已成功SHA1与封面阶段复用，目录只做有界输入复核。后台发布同时校验页序代次和完整解析输入指纹，等价编码切换也不能被迟到工作器覆盖。推荐冻结输入及健康缓存身份包含相应解析输入；人工资料、分组和评分算法不改。

共享图片预算配置项`image_memory_mib`可省略（512MiB），允许32–8192；设0同默认。仍有两并发图片处理槽、像素及解压限制。代表页SHA1使用32KiB流式缓冲、长度与ZIP CRC核验，不完整解码；SHA1成功不代表每页解码验证成功。

### 存储响应与一次清理确认

`GET /api/v1/maintenance/storage`仅管理员可用。保留`categories/protected`，增量包含四个`groups`（`long_term/rebuildable/temporary/recovery`）、`total_bytes/cleanable_bytes/protected_bytes/statistics_at/cache_seconds`、`operations`和`suggested_categories`。分组与内部kind分开；每项包含文件数、可清理／保护数和字节数，以及按原因累计的字节数。所有计数来自同一不重叠走盘清单，未知数据保留，不计源漫画。多项DB关系批量读取，正常轮询复用30秒缓存；显式`?refresh=true`重新统计，清理后自动失效。

仍使用`POST /maintenance/plans`创建`operation=cleanup`预览、原执行接口一次确认。cleanup在完成认证、CSRF和普通时限内的JSON解析后，使用独立有限30分钟bulk校验／响应时限；客户端取消、断连和更短的上游deadline仍生效，其他接口与其他operation继续普通30秒。前端保留选择并展示可取消的等待状态，请求等待预算覆盖30分钟及响应开销，不自动重复提交；成功才展示冻结计划。504 `request_timeout`表示预览停止，尚未执行删除；422 `cleanup_preview_capacity`表示需缩小类别／操作选择。单次候选限制10万文件、1TiB，先检查预算后流式哈希；统计和冻结清单共用一次新遍历，仅所选文件哈希一次。普通storage轮询复用30秒缓存且不哈希候选。计划30分钟有效期从创建成功开始计算，不消耗预览读取时间。

可用`options.operation_ids`选择`operations`返回的材料ID（如`instance:操作ID`或`health:修复ID`），省略时按类别预览全部可用材料；这不是文件路径。`options.categories`新增：

| category | 用途 |
| --- | --- |
| redundant_covers / redundant_tag_images | 仅当前无用途缩略图，默认建议 |
| instance_recovery | 已结束恢复工作副本、校验／准备暂存；用户backup的archive.zip保持 |
| health_rollback | 已完成或已回退修复的登记材料；未完成修复及日志保持 |
| migration_originals | 已通过离线档案核验且无引用的迁移原图 |
| covers / tag_images | 保持旧显式全清语义，作为有效缓存清理的次级操作 |
| import_preview_cache / recommendation_indexes | 次级清理；无活动或暂停任务时可清候选展示缓存、可重建特征文件，系列冻结证据继续保护 |

`tmp/snapshots/orphan_assets/terminal_jobs`旧类别保留。临时文件遇到活动／暂停任务时保护；最新`.sqlite`升级快照及升级说明记录保留，执行时再次核对最新快照。通用orphan_assets始终排除treec-originals，不能绕过核验。次级特征清理只删可重建特征及对应缓存索引，不删模型、冻结系列证据或采纳历史；后续明确启动推荐时可能重新计算，清理本身不启动模型或联网。

预览的`summary.storage.planned`沿用现有嵌套位置，包含`files/bytes/protected_files/protected_bytes/impacts/clears_valid_caches`。材料影响在同一面板说明；仍有效的实例回退材料会标注`removes_rollback_point`。清理不再复制整实例。执行逐文件核对SHA256、设备／inode、长度、mtime，持写事务复核引用和全局操作；新引用、新替换对象不删。`summary.cleanup_result`持久返回`released_bytes/deleted_files/skipped_files/failed_files/next_index`，逐项推进检查点，重启保留已确认释放量。若进程恰在unlink后、SQL提交前中断，重启将缺失对象计为跳过，不虚报已经确认的释放量，同时在复核旧身份及当前引用后收尾孤儿assets／特征登记、将对应health_artifacts.pinned置0，保留健康历史；已退役材料不再成为标准备份的必要引用；数据库与文件系统不宣称跨介质原子提交。

材料第一次删除前持久写入`storage_material_receipts`的cleaning状态，完成后cleaned；终态日志／清单保留。历史实例操作和健康修复返回`materials_cleaned`（表示材料清理已开始或完成、回退不可再用），全局激活收据同步标记；正常启动和历史读取继续可用。无主库记录的旧离线失败预览须通过上传包与本地manifest一致性识别，只列已知成员，不伪造completed操作；未知目录、日志和清单不删。

### 转换工具的原图清单契约

独立转换工具在外部转换档案中提供UTF-8 JSON清单，格式如下；路径仅相对清单所在目录，SHA256必须是真实文件字节摘要，禁止`..`、绝对路径及符号链接。清单可以包含比当前实例更多的原图，重复内容按摘要对应；所有实例登记原图都必须找到匹配大小／摘要的外部文件，否则整次核验不写新收据。

```json
{"format_version":1,"files":[{"key":"originals/anonymous.png","size":1234,"sha256":"64位十六进制SHA256"}]}
```

应用已正常停止、schema27升级完成后，由用户明确执行：

```sh
make storage-verify STORAGE_CONFIG=/absolute/private/config.json ORIGINALS_MANIFEST=/absolute/conversion/archive/originals.json
```

命令使用普通实例独占锁，仅以只读连接打开指定主库，不执行迁移、启动整理、扫描或任务。逐一哈希外部与实例原图后，在`data/health/storage-original-verification.json`保存0600私有记录，绑定当前主库设备／inode、清单摘要、原图ID／摘要／大小和外部成员身份；stdout仅输出核验数量及`deletion_performed:false`。外部路径不会出现在网页、任务公共结果或Git。记录随后续标准整实例备份保留，整实例恢复导致主库文件身份变化，或外部档案不可达时保持保护，需重新明确核验。本命令只读核验已准备好的目录／JSON清单，**不支持直接读取正式`conversion-archive.zip`，也不自动解包**。独立转换工具须通过另一个明确执行的命令，在新目录中生成核验用原图与上述清单；旧ZIP、旧恢复包保持原样，不能以网页选择路径代替这个步骤。该转换命令尚须既有转换对话实施，不能把本后端CLI称为ZIP直读已完成。清理时再验证清单和外部原图摘要，并在删除事务内检查素材身份与当前引用；外部档案从不写入或删除。
