## 输入与任务

直接读取用户已确认的Work/Edition关系及有效题名/标签，只准备MiniLM标题特征；缺缓存时使用固定本地模型补算，不下载、不计算封面向量。全部版本提供题名证据，Work只占一个系列位置；缺源但已有资料仍可参与。已有系列固定，不自动拆合/转移；目标资料不完整时保留关系并显示未参与加入的诊断。

新增010，001–009保持字节和校验和。扩展任务类型及六张系列发现/证据/方案/成员/待核对/决策表；重绑定任务外键，保留旧任务、检查点、决策及撤销数据。代码schema10共62表，建库身份仍foundation-v1。任务冻结输入，按特征和Work行保存检查点，暂停/取消递增代次，旧执行结果不能发布。来源/组织变化分别检查指纹和revision，不混用输入。与同作品任务共用单CPU工作器，2GiB软预算，最多6000 Work/2000万比较/25万去重召回边，超限明确失败，不静默截断。

## API和事务

所有接口位于`/api/v1`，保留认证、Origin、CSRF及JSON错误，详细请求/响应以OpenAPI为准。

| 接口 | 能力 |
|---|---|
| POST /series-discovery-jobs | 按书库冻结并启动，202+job_id |
| GET /series-proposals、/{id}、/{id}/members | 方案与历史查询、真实成员分页 |
| GET /series-discovery-jobs/{id}/pending | 待核对Work、最多三个备选及目标可用性诊断 |
| POST /series-proposals/{id}/resolve | 重验成员选择、名称和顺序，不改变组织 |
| POST /series-proposals/{id}/accept、dismiss、restore、undo | 采纳、忽略、恢复和撤销 |

创建至少两个未归属Work，加入只添加未归属Work，最多1000 Work/同书库。旧任务只使用显式卷号，否则自然排序/追加；新任务采用下文独立命名与排序规则。卡片允许排除、名称和上/下移；已有系列名称和既有相对顺序保持，改名使用系列管理。

resolve只接受原方案成员子集，后台复核全组后返回新的可见方案；accept不接受客户端组织命令或临时改名/排序。约束、CAS、现有组织规划器、组织写入及决策同一事务；重复采纳幂等。忽略不推导每对成员无关。Undo只撤销本次Series变更，验证目标及相关Work后续revision，不恢复/覆盖Edition资料或文件。

采纳/撤销后后台复用证据重建受影响方案；无关方案revision及已resolve草稿保留。已忽略/采纳/撤销历史持久保存，不被重建覆盖。包含系列方案的任务暂受终态任务清理保护，保留再次重验所需冻结证据；没有新增自动清理。源漫画、Work归属及首选版本、来源、人工标签、收藏不随系列操作改变。

## 网页与试用边界

入口为`/admin/series-recommendations`，与同作品整理并列。组成系列、加入已有系列、待核对/备选三个区域；可直接核对采纳，无关系标注或研究分数。分页、状态及书库在URL中；草稿保留在页面会话，通知/轮询只提示更新，不静默重设提交版本。名称、排除和排序改动先更新方案；移动端可用按钮完成排序。

## 2026-10-22：新任务的名称与排序

`series-presentation-v2`是独立Go纯函数，不参与评分、召回、聚类或模型输入。匹配用的完整题名、冻结V2参数和Python结果保持不变；原有大小写不再被匹配规范化带进展示名。新任务在已有context_json中冻结展示版本，不新增SQL或修改001–010；旧任务缺失版本时保持旧逻辑，包括恢复和后台重验。未知版本明确拒绝。后台只重验每库最新已完成任务，同秒任务使用创建行序打破平局，防止旧轮次覆盖新结果。

新系列名综合全部Edition题名，删除常见中英日成对括号及其中内容（含嵌套），整理空白/分隔符；去除明确卷/话/篇、上下前后篇序号。裸数字及罗马后缀需组内共同主体和不同位置证据，不能机械删掉007、1984、3×3等固有数字。分隔明确且不同篇名支持同一主体时，可将“共同题名 修学旅行篇／共同题名 海边篇”命名为“共同题名”；证据不足、不完整括号导致名称为空或只剩序号时要求人工命名，不拿带括号原标题兜底。人工填写的名字不再自动清洗。

排序优先明确同类型位置，其次共同主体支持的裸数字。唯一无编号本篇在续作前，但不把它的资料写成第1卷：`Sukumizu Sentai Bikininger → … 2 → … 3`。多个无编号、重复/混合位置或同Work版本题名序号冲突时，使用去装饰后的题名自然排序并提示核对。加入保留既有相对顺序；可确定位置才插入，否则新增追加末尾。手动改序始终显式保存。

API增量返回可选`name_required`、`order_basis`（explicit/contextual/natural/existing/manual），保留name/order/order_uncertain及旧响应兼容。空建议名不能采纳，填名并resolve后才解除限制。卡片说明实际排序依据，不再全部称为自然排序。新展示版本使用不同方案身份，按相同成员和输入延续旧忽略；恢复新方案不会删除旧忽略记录，旧名称和顺序不原地改写。

适用边界：只在用户下一次启动新的“查找系列”任务后启用。“刷新系列方案”只是查询已有结果，不能把旧任务升级成新规则；既有系列、已采纳和旧手工方案不会批量改名或重排。
